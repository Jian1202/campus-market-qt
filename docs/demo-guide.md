# 实验演示步骤

## 准备

在 Release 交付包的“运行程序”目录双击 `运行演示.cmd`；自行构建后也可双击构建输出目录内的同名启动器。演示数据预置两笔完成订单、一个低信用活跃卖家、商品/用户各三条待处理举报。所有样本均为虚构教学数据。

账号：小张 `202600000001`、小李 `202600000002`、小王 `202600000003`、小陈 `202600000004`，学生密码 `123456`；管理员 `admin / admin123`。

## 1. 注册与发布

注册任意未使用的12位数字学号。登录后发布商品，填写标题、分类、价格、成色和说明，可选上传图片。首页能看到刚发布的商品。输入“平板”可演示标题/描述全文索引，输入单字可演示 LIKE 回退。

## 2. 一条完整交易

1. 小李登录，打开小张发布的“自用平板电脑”，点击“发起购买请求”。
2. 退出登录，换小张，点击窗口顶部“交易 / 信用 / 举报 / 报表”，在“购买请求”中接受小李的请求。
3. 首页不再显示该商品，数据库商品状态为 reserved，正式订单状态为 confirmed。
4. 换小李，在“我的订单与互评”点“确认收货”。商品状态 sold，订单 completed。
5. 小李点击“评价对方”打分，再换小张评价小李。观察信用分变化；同一方的评价入口消失。
6. 在数据库查看 Review：该订单恰好一行，两组评分都已填写。

## 3. 订单一对多与一次成交

用另一件商品演示：买家请求 → 卖家接受 → 任一方取消 → 买家再次请求 → 卖家再次接受 → 买家确认收货。TradeOrder 中同一 goods_id 有两行，一笔 cancelled、一笔 completed；唯一生成列索引防止重复有效订单。

多名买家在卖家接受之前均可请求，卖家只接受一人，其他待处理请求自动拒绝。重复发起同一待处理请求会失败。

## 4. 商品与用户举报

普通用户在详情页“举报商品”或“举报卖家”填写原因，然后在“我的举报”查看状态。原始演示数据已让“期末复习资料”和小张各达到3位举报人，可直接展示阈值筛选。

管理员进入交易中心：

1. “多表统计报表”选择商品/用户举报超过阈值，阈值设2，可见预置风险记录。
2. “举报处理”填写核实说明，执行下架或冻结；也可填写理由驳回。
3. 下架后的商品不再出现在首页，Goods 仍能查到，is_deleted=1；未完成订单取消，历史完成订单不变。
4. 用户冻结后登录失败；已登录的旧会话执行发布、请求、评价等写操作也会重新检查冻结状态。
5. 原管理员个人中心可解冻用户；解冻后违规商品保持下架。

## 5. 展示三张以上连接报表

管理员交易中心“多表统计报表”依次展示：分类成交均价、低信用活跃卖家（阈值80）、订单交易明细、商品风险、用户风险。对应独立 SQL 在 `database/reports.sql`。

建议先展示预置报表，再做举报处置，以免处理完成后风险列表按定义变空。

## 6. 答辩常见问题

- 为什么用购买请求表？题目要求卖家确认后才生成订单，提前记录意向可避免混淆“请求”和“成交订单”。
- 为什么评价不是两行？为了同时满足 order_id UNIQUE 和双方互评，以一行承载两方独立且不可覆盖的评价。
- 为什么预订商品首页不可见？每件校园闲置商品默认只有一件，已接受购买请求后不能继续当作可立即购买。
- 如何防止同一商品卖两次？事务、行锁、条件更新，再加 MySQL 生成列唯一索引兜底。
- 举报商品和用户怎么保证对象存在？用两个外键和二选一 CHECK，不能只存无外键的 target_id。
- 信用分谁维护？MySQL AFTER UPDATE 触发器，按评价接收方全部历史评分计算；不会在界面里只改一个显示数字。
- 下架后为什么报表仍有成交记录？软删除仅影响公开列表，不改变历史事实。
